# alignment-check

掃描 wiki 條目中的「補充資料」段落，判斷主題是否真正屬於該條目，找出歸屬錯誤的內容並建議修正方向。

raw-pipeline Agent C（v1.3.0 起）在補充前會做基本 T 層驗證，但屬於單條目比對。alignment-check 做的是全庫深度掃描：跨條目比對、找出已補充但仍有偏移的段落，作為 Agent C 的事後驗證層。

## 使用方式

```
alignment-check
對齊檢查
wiki 內容對齊檢查
```

建議在以下時機執行：
- raw-pipeline 跑完大批次（≥ 3 批）後
- wiki-health-check 之前（先確保內容位置正確，再做整體健檢）
- 手動發現明顯歸屬錯誤時

---

## 執行流程

```
1. 讀取 wiki/INDEX.md 取得所有條目清單
2. 逐一讀取每個 wiki 條目，提取：
   - T 層核心論點（條目的主題定義）
   - 所有「## 補充資料」段落（標題 + 內容）
3. 對每個補充資料段落：
   - 判斷該段落的核心主題是什麼
   - 對比 T 層：主題是否直接相關？
   - 若不相關：掃描現有 wiki 條目，找最適合的歸屬目標
4. 彙整報告，存入 outputs/alignment-check-YYYY-MM-DD.md
```

## 對齊判斷標準

### ✅ 對齊（保留）
補充資料的核心主題落在以下任一範圍內：
- 直接延伸或深化 T 層論點
- 提供 T 層論點的具體案例、數據或反例
- 說明 T 層工具/方法的安裝、設定、版本資訊

### ⚠️ 邊緣（標記，人工判斷）
- 補充資料與 T 層有間接關聯，但核心主題不同
- 補充資料涉及多個主題，部分對齊、部分不對齊
- 補充資料是同一作者的另一個工具/框架介紹

### ❌ 不對齊（建議搬移）
- 補充資料的核心主題明顯屬於另一個現有條目
- 補充資料的主題完全獨立，應建立新條目
- 補充資料是對條目主題的誤解（Agent 分類錯誤）

## 執行後的修正方式

alignment-check **只產出報告，不自動修改檔案**。

確認報告後，可用以下指令讓 Claude Code 執行修正：

```
根據 outputs/alignment-check-YYYY-MM-DD.md 的建議，
將 [[來源條目]] 中的「### 不對齊段落標題」搬移至 [[目標條目]]
```

或一次修正所有不對齊項目：

```
根據 outputs/alignment-check-YYYY-MM-DD.md，
執行所有「不對齊」的搬移建議（⚠️ 邊緣項目跳過）
```

## 與其他 Skill 的分工

| Skill | 檢查範圍 | alignment-check 的差異 |
|-------|---------|----------------------|
| `wiki-health-check` | 矛盾、孤立筆記、懸空連結、過時內容 | 不檢查段落歸屬 |
| `raw-pipeline` Agent C | 避免重複條目 + 補充前基本 T 層驗證（v1.3.0）| 單條目比對，不做全庫深度掃描 |
| `alignment-check` | 每個補充資料段落是否放對位置 | 專項補這個盲點 |

建議執行順序：`alignment-check` → `wiki-health-check` → `knowledge-synthesizer`
