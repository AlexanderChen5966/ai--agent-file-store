## v4 核心動機：動態模型分配

v3 解決了架構問題（三 reviewer、壓縮協議、分層 review、diff-only）。
v4 的目標是在 v3 架構上，套用 **Pilot Suite 模型分配邏輯**，讓每個角色根據任務複雜度動態選擇最適合的（最便宜的）模型。

> **重要發現（2026-05-08 實測）**
> Copilot Pro 帳號中，**GPT-5 mini（0x）和 GPT-4.1（0x）完全免費**。
> 這意味著 reviewer 升級路徑存在大量免費空間，v4 的成本節省主要來自此處。

## 變更一：Developer 動態模型選擇

### 現狀（v3）
```
copilot-developer → claude-sonnet-4.6（永遠，1x）
```

### v4：根據任務複雜度動態選擇

| 任務類型 | 判斷條件 | 使用模型 | 成本 |
|---|---|---|---|
| **簡單** | ≤2 檔、typo / i18n / 小 UI 調整 | GPT-5 mini | **FREE** |
| **標準** | 3–9 檔、一般功能、bug fix | GPT-5.4 mini | 0.33x |
| **複雜** | ≥10 檔、跨模組、架構設計 | GPT-5.3-Codex | 1x |
| **安全/金流** | 關鍵字含 security / payment / auth | GPT-5.3-Codex | 1x |

Team Lead 在寫 task context file 前先評估並在 TASK dispatch 中明確指定模型：

```bash
# 簡單任務
cat $TASK_FILE | copilot --model gpt-5-mini \
  --allow-all-tools --autopilot -p "..." 2>&1

# 標準任務
cat $TASK_FILE | copilot --model gpt-5.4-mini \
  --allow-all-tools --autopilot -p "..." 2>&1

# 複雜/程式碼密集任務
cat $TASK_FILE | copilot --model gpt-5.3-codex \
  --allow-all-tools --autopilot -p "..." 2>&1
```

> **⚠️ 待驗證**：`--allow-all-tools --autopilot` 是否與 GPT-5 mini / Codex 模型相容，需實機測試後確認。

## 變更三：更新 Level 定義

### v4 Level 對應表

```
Level 1 — 快速掃描（--quick）
  copilot-reviewer: GPT-5 mini（FREE）
  claude-reviewer:  跳過
  gemini-reviewer:  gemini-3.1-flash-lite-preview
  適合：typo、i18n、小 UI 調整
  耗時：~20s

Level 2 — 標準 Review（預設）
  copilot-reviewer: GPT-4.1（FREE）
  claude-reviewer:  native Claude subagent（平行）
  gemini-reviewer:  跳過（節省免費額度）
  適合：一般功能、bug fix
  耗時：~2 min

Level 3 — 深度 Review（--deep）
  copilot-reviewer: GPT-5.4 or GPT-5.3-Codex（1x）
  claude-reviewer:  native Claude subagent（平行）
  gemini-reviewer:  gemini-3-flash-preview（平行）
  適合：架構變更、高風險模組、安全/金流
  耗時：~3 min
```

> **Level 2 移除 Gemini** 的理由：
> Level 2 的 claude-reviewer 已涵蓋需求對齊與缺少場景的檢查。
> Gemini 免費額度有限，保留給真正需要的 Level 1 和 Level 3。

### Level 自動升級規則（量化，採用 Pilot Suite 閘門模式）

```
Level 1 發現任何 C → 自動升級 Level 2（通知使用者）
Level 2 發現 C 且檔案含關鍵字（security/payment/auth/oauth）→ 建議升 Level 3（詢問使用者）
任務跨 ≥10 個檔案 → 起點直接設定為 Level 3
```

## 變更四：更新 Fallback Chain

### Copilot Fallback（v4）

```
Level 3 developer:  GPT-5.3-Codex → GPT-5.4 mini → GPT-5 mini（FREE）→ FAIL
Level 2 developer:  GPT-5.4 mini → GPT-5 mini（FREE）→ FAIL
Level 1 developer:  GPT-5 mini → Claude Haiku 4.5 → FAIL

Level 3 reviewer:   GPT-5.4 → GPT-5.3-Codex → GPT-4.1（FREE）→ GPT-5 mini（FREE）→ SKIP
Level 2 reviewer:   GPT-4.1（FREE）→ GPT-5 mini（FREE）→ SKIP
Level 1 reviewer:   GPT-5 mini（FREE）→ SKIP
```

### Gemini Fallback（v4）

```
Level 3: gemini-3-flash-preview → gemini-2.5-flash → gemini-3.1-flash-lite-preview → SKIP
Level 2: 不使用 Gemini（保留額度）
Level 1: gemini-3.1-flash-lite-preview → gemini-2.5-flash → SKIP
```

## 架構圖（v4）

### Dev Team

```
User (Commander)
  │
Team Lead（當前 Claude session）
  │  評估任務複雜度 → 決定 developer tier + review level
  │
  ├── copilot-developer（動態 tier）
  │     簡單：GPT-5 mini（FREE）
  │     標準：GPT-5.4 mini（0.33x）
  │     複雜：GPT-5.3-Codex（1x）
  │
  ├── copilot-reviewer（Level 動態 tier）
  │     L1: GPT-5 mini（FREE）
  │     L2: GPT-4.1（FREE）
  │     L3: GPT-5.4 / GPT-5.3-Codex（1x）
  │
  ├── claude-reviewer（L2 / L3 only）
  │     native subagent，架構/maintainability
  │
  └── gemini-reviewer（L1 / L3 only）
        L1: gemini-3.1-flash-lite-preview
        L3: gemini-3-flash-preview
```

### Content Team

```
User (Commander)
  │
Team Lead（當前 Claude session）
  │  評估文件類型 → 決定 author tier + review level
  │
  ├── author（動態 tier）
  │     簡單文件：native Claude subagent（現有）
  │     複雜文件：native Claude subagent（現有，不變）
  │     ※ Author 目前不走 copilot CLI，維持原設計
  │
  ├── copilot-reviewer（Level 動態 tier）
  │     L1: GPT-5 mini（FREE）
  │     L2: GPT-4.1（FREE）
  │     L3: GPT-5.4（1x）
  │
  ├── claude-reviewer（L2 / L3 only）
  │     native subagent，可讀性/風格一致性
  │
  └── gemini-reviewer（L1 / L3 only）
        L1: gemini-3.1-flash-lite-preview
        L3: gemini-3-flash-preview
```

## 變更五：Content Team 動態模型分配

### 複雜度判斷條件（與 dev team 不同）

| 文件類型 | 複雜度 | Author tier | Review Level |
|---|---|---|---|
| 更新紀錄、小改動說明、i18n 說明 | 簡單 | native Claude | Level 1 |
| 功能需求文件、任務文件（如 annotation_name_task） | 標準 | native Claude | Level 2 |
| 跨系統架構設計、API 規格、技術決策文件 | 複雜 | native Claude | Level 3 |

> Author 維持 native Claude subagent，不走 copilot CLI。
> 差異在 **reviewer 的模型 tier** 和 **review level 選擇**。

### Content Team Review Level 定義（v4）

```
Level 1 — 快速掃描（--quick）
  文件類型：更新紀錄、小改動說明
  copilot-reviewer: GPT-5 mini（FREE）
  claude-reviewer:  跳過
  gemini-reviewer:  gemini-3.1-flash-lite-preview
  焦點：明顯錯誤、格式問題
  耗時：~20s

Level 2 — 標準 Review（預設，需求文件主要走這層）
  文件類型：功能需求、任務文件
  copilot-reviewer: GPT-4.1（FREE）   焦點：邏輯一致性、遺漏條件、矛盾需求
  claude-reviewer:  native Claude     焦點：可讀性、結構、受眾適切性
  gemini-reviewer:  跳過（節省免費額度）
  耗時：~2 min

Level 3 — 深度 Review（--deep）
  文件類型：架構設計文件、跨系統 API 規格、技術決策
  copilot-reviewer: GPT-5.4（1x）     焦點：邏輯嚴謹性、技術正確性
  claude-reviewer:  native Claude     焦點：完整性、可維護性
  gemini-reviewer:  gemini-3-flash-preview  焦點：遺漏情境、邊界條件
  耗時：~3 min
```

### Content Team Level 自動升級規則

```
文件提及跨 ≥3 個模組/系統 → 起點設為 Level 2
文件含 API endpoint / 資料庫結構 / 安全機制 → 建議 Level 3（詢問使用者）
Level 1 發現 C（邏輯矛盾 / 關鍵遺漏）→ 自動升級 Level 2
```

### Content Team Reviewer 焦點對照

| Reviewer | Dev Team 焦點 | Content Team 焦點 |
|---|---|---|
| copilot-reviewer | bugs、security、performance | 邏輯一致性、遺漏條件、矛盾需求 |
| claude-reviewer | 架構、設計模式、maintainability | 可讀性、結構、受眾適切性、風格 |
| gemini-reviewer | spec compliance、missing scenarios | 完整性、缺少情境、邊界條件、主題對齊 |

### Content Team Gemini Fallback（v4）

```
Level 3: gemini-3-flash-preview → gemini-2.5-flash → gemini-3.1-flash-lite-preview → SKIP
Level 2: 不使用 Gemini（保留額度）
Level 1: gemini-3.1-flash-lite-preview → gemini-2.5-flash → SKIP
```
