## 輸入前處理 SOP

### 逐字稿前處理

直播/逐字稿的噪音密度最高，前處理是最重要的步驟。

**識別並丟棄（不進入四層判斷）：**
```
純情緒反應：「哇！」「對對對！」「嗯嗯」「好厲害」
重複確認：「你懂我意思嗎」「就是這樣」「不是嗎」
說話者標記：「主持人：」「Axton：」→ 保留內容，去掉標記
時間填充：「那個...」「就是說...」「然後呢...」
廣告/贊助段落：直接識別並整段跳過
觀眾互動回覆：「感謝XXX的提問」「剛才有人問到」→ 只保留回答內容
```

**合併破碎句子：**
- 同一個想法跨多行說完 → 合併成一個條目再判斷
- 判斷依據：意思是否完整、是否有新資訊加入

**說話者區分：**
- 多人對話 → 每個說話者的觀點獨立成條目
- 不同說話者對同一議題有不同立場 → 在素材庫模式下標記來源

---

### 字幕檔前處理

**剔除時間戳：**
```
格式 1：00:01:23 → 直接刪除
格式 2：[00:01:23] → 直接刪除
格式 3：1\n00:00:01,000 --> 00:00:03,000 → 刪除序號和時間行
```

**合併斷句：**
字幕按時間切割，一個完整句子可能跨 3-5 行。合併規則：
- 以句號/問號/驚嘆號作為句子結束
- 合併後長度超過 200 字的段落 → 保留為一個完整段落條目

---

### 網頁文章前處理

**識別正文邊界：**
- 正文開始：文章標題之後的第一個完整段落
- 正文結束：「相關文章」「你可能也喜歡」「留言區」「版權聲明」之前

**丟棄非正文區塊：**
```
導覽列文字（首頁、關於、聯絡）
廣告標語和產品推薦
社群分享按鈕文字
作者簡介（除非文章本身是分析作者觀點）
「繼續閱讀」「展開全文」等UI文字
```

**保留但標記：**
- 圖片說明文字 → 保留，標記為 `[圖說]`
- 引用塊 → 保留，標記來源（若有）

---

### 純文字筆記前處理

最乾淨的輸入，通常不需要前處理。僅需：
- 確認是否有標題層級（若有，按層級分段再處理）
- 確認是否為條列式（若是，每條獨立進入四層判斷）

## TBRC 框架放置邏輯

TBRC 適合有明確論點和實踐路徑的內容。

### 放置對照表

| 評級 | 放置位置 | 說明 |
|------|---------|------|
| ⭐⭐⭐⭐⭐ | T層：核心論點 | 最重要的一句話定義或洞察 |
| ⭐⭐⭐⭐ | R1-R2：理解與架構 | 支撐論點的概念比較或架構說明 |
| ⭐⭐⭐ | R3-R4：實踐與應用 | 具體案例、操作步驟、實測結果 |
| ⭐⭐ | C3：延伸資源 | 推薦閱讀、工具、補充資料 |
| ⭐/❌ | 丟棄 | — |

### 各層填寫規則

**T層（Thesis）：**
- T1 本質定義：「X 是什麼」的精確定義（🔥 優先直接引用）
- T2 核心價值：「X 的重要性在於」
- T3 關鍵洞察：「X 和一般認知的不同點是」

**B層（Boundary）：**
- B1 適用場景：哪些情況下這個論點成立
- B2 限制條件：需要哪些前提
- B3 不適用：哪些情況下這個論點不成立（常被忽略，但對 Agent 很重要）

**R層（Racetrack）：**
- R1 理解對比：和類似概念的差異
- R2 架構設計：如何系統性實作
- R3 實踐場景：具體的使用案例
- R4 部署應用：落地的注意事項

**C層（Closure）：**
- C1 核心要點：3條以內的精華摘要
- C2 行動清單：下一步可以做什麼（動詞開頭）
- C3 延伸資源：文章、工具、人名

## SCQA 框架放置邏輯

SCQA 適合有問題、有轉折、有解法的敘事結構。

### 四個位置

**S（Situation）情境：**
放置：描述初始狀態、背景脈絡的條目
問自己：「這段描述的是事情發生前的樣子嗎？」→ 是 → S

**C（Complication）衝突：**
放置：描述問題、挑戰、意外、打破預期的條目
問自己：「這段描述的是哪裡出了問題或不如預期？」→ 是 → C

**Q（Question）核心問題：**
從 S 和 C 中萃取：「在這個情境下，核心問題是什麼？」
通常不在原始內容中直接出現，需要歸納。
格式：一句疑問句

**A（Answer）解答：**
放置：解決方案、結論、行動的條目
問自己：「這段描述的是如何應對 Q 的問題？」→ 是 → A

### SCQA 特別規則

- C 不是「問題清單」，是「讓原本 S 站不住腳的關鍵矛盾」
- Q 必須由你歸納，不能直接複製原文
- A 必須和 Q 對應，若 A 沒有回答 Q → 標記 ⚠️ 解答未完整回應問題

## 素材庫框架放置邏輯

素材庫不套框架，只做分類和標籤。適合內容密度高、主題多元的逐字稿或字幕。

### 素材條目結構

每條素材：
```
【標籤】主題標籤1 / 主題標籤2
【內容】精煉後的文字（📝 改寫 或 🔥 原話）
【可信度】✅ / ⚠️ / ❌
【來源】說話者 / 時間戳（若有）
```

### 標籤規則

- 每條素材 1-3 個標籤
- 標籤來自內容本身，不預設分類體系
- 使用名詞或名詞片語：「狀態管理」「API設計」「職涯建議」
- 不使用動詞標籤：不用「如何」「學習」「實作」
- 若使用者有指定標籤體系，優先使用使用者的

### 素材庫輸出格式

依標籤分群輸出，讓使用者可以快速找到某個主題下的所有素材。

## 情境腳本框架放置邏輯

情境腳本適合將內容轉化為角色扮演訓練材料或教學對話。

### 腳本元素

**情境設定：**
- 場景：在哪裡、什麼時間點
- 角色：有哪些角色、各自的背景和目標
- 觸發事件：對話是因為什麼開始的

**對話段落：**
- 每個回合只有一個說話者
- 每句話推進情境或揭示資訊
- 避免一次說太多（每個回合 1-3 句）

**學習重點標記：**
在關鍵對話後標記：`[重點：這裡示範了 XXX 技巧]`

### 從原始內容轉換為腳本的規則

1. 找出原始內容中的核心論點或技巧（⭐⭐⭐⭐ 以上）
2. 設計一個能讓這個論點自然出現的情境
3. 設計角色：一個需要學習的角色 + 一個展示正確做法的角色
4. 把論點轉化為對話，不直接說教
5. 結尾要有明確的情境結果（不能懸空）

## 四層判斷邊界案例

### 案例 1：情緒中帶有資訊

原文：「我超討厭那些說『AI 會取代你』的人，因為根本就是瞎說，AI 只是把你不會的事情變得更容易做到，它不能替代你的判斷力」

判斷：
- 情緒部分（「超討厭」）→ 🗂️ 或丟棄
- 核心觀點（「AI 只是把你不會的事情變得更容易做到，不能替代判斷力」）→ ⭐⭐⭐⭐⭐，📝 改寫，⚠️（個人觀點無來源）

---

### 案例 2：重複但有新細節

原文第一次：「要先理解需求再寫code」
原文第二次：「要先理解需求再寫code，特別是在不熟悉的領域，不然很容易做出技術上正確但業務上沒用的東西」

判斷：第二次有新細節（不熟悉領域的條件、技術正確但業務沒用的說明）→ 保留第二次，第一次丟棄

---

### 案例 3：有數字但來源不明

原文：「現在有 80% 的開發者在用 AI 工具」

判斷：⭐⭐⭐，🗂️ 打標籤，❌ 無來源 → 不放入主體，在素材庫標記 `需查核來源`

---

### 案例 4：純個人感受

原文：「這個工具用起來真的很順，推薦大家試試看」

判斷：⭐⭐（只有正向評價，無具體理由）→ 丟棄，或在素材庫模式下標記 `💬 使用者評價` 但不放入知識主體
