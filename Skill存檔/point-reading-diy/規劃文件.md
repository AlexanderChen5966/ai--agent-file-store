# point-reading-diy Skill 規劃文件

> 狀態：實作中——⑤ 打包前暫停，等使用者回家用實體貼紙報碼（見第 10 節）
> 建立日期：2026-10-05
> 目的：讓 agent 協助把音檔切成一段段，對應到卡米點讀筆的「內容貼」，最後打包成點讀筆可用的 DAB 點讀包。

---

## 1. 背景

卡米點讀筆可以用「普通書名貼 + 內容貼」把沒有點讀碼的一般書變成點讀書：

1. 普通書名貼貼在封面，代表「這本書」
2. 內容貼貼在書裡每個想點讀的位置，每張有自己的號碼
3. 每張內容貼要有一段對應的 MP3，打包成點讀包放進筆裡

最花時間的是第 3 步：把一整段錄音切成一句一檔、再一一對到內容貼號碼。這個 Skill 要把這件事自動化。

打包部分沿用已完成並實測成功的 `dab_tool.py`（AP4 → DAB 專案中開發，Max & Mousy 已在舊卡米筆上驗證可用）。

---

## 2. 為什麼選 Skill（而不是 MCP 或獨立工具）

| | Skill | MCP | 獨立工具 |
|---|---|---|---|
| 開發成本 | 低 | 中 | 低～中 |
| 修改 | 改完即生效 | 需重啟 server | 需重新打包 |
| agent 彈性 | 高，可臨場寫程式處理特例 | 只能用預先定義的函式 | 無 agent |
| 適合 | 流程還在摸索、每本書情況不同 | 流程固定、多工具共用 | 完全不需判斷的重複操作 |

選 Skill 的理由：

- 靜音門檻每份錄音都不同，需要 agent 試切、看結果、再調參數
- 片段對應到內容貼號碼需要模糊比對，寫死在 MCP 函式裡反而綁手綁腳
- 異常（黏在一起沒切開、只有雜音、少一段）靠 agent 判斷比寫規則容易

**升級成 MCP 的時機**：要在沒有執行環境的地方使用、要給其他 AI 工具共用、流程已穩定。屆時建議把功能併入現有的 media-downloader MCP，而不是另開一個。

## 3. 整體流程

```
原始音檔 ──► ① 切檔 ──► ② 語音辨識 ──► ③ 人工審核 ──► ④ 對應內容貼 ──► ⑤ 打包 DAB ──► 放進筆
             (靜音偵測)   (Whisper)     (審核網頁)      (單字表比對)     (dab_tool)
```

| 步驟 | 由誰做 | 說明 |
|---|---|---|
| ① 切檔 | 腳本 + agent 調參 | ffmpeg silencedetect 依靜音切；agent 依段數是否合理調整門檻與最短靜音長度 |
| ② 語音辨識 | 腳本 | Whisper 本機執行，給每段配文字；國語結果用 OpenCC 轉繁體 |
| ③ 人工審核 | 人 | 產生審核網頁：每段可播放、顯示辨識文字、可標記問題段 |
| ④ 對應內容貼 | agent + 腳本 | 依單字表模糊比對，決定哪段對哪張內容貼並改名（如 `461.mp3`） |
| ⑤ 打包 | 腳本 | `dab_tool.py` 產生 DAB，檔名前綴依書名貼規則 |

**人工審核不可省略**：切點準不準、念的對不對，最後一定要有人聽過。

## 4. 資料夾結構（規劃）

```
point-reading-diy/
├── SKILL.md            ← agent 的操作說明與判斷原則
├── 規劃文件.md          ← 本文件
└── scripts/
    ├── split.py        ← 依靜音切檔，輸出片段與時間點清單（JSON）
    ├── split_asr.py    ← 依 Whisper 時間點切檔（有背景音樂時）
    ├── transcribe.py   ← 語音辨識，給每段配文字
    ├── review.py       ← 產生審核網頁（波形、播放鍵、標記）
    ├── assign.py       ← 依單字表或順序對應內容貼號碼並改名
    ├── synth.py        ← Mac `say` 批次合成（無錄音時）
    ├── _common.py      ← 共用函式
    └── dab_tool.py     ← 打包 DAB（沿用現成版本，待放入）
```

## 5. 語言支援

| 步驟 | 受語言影響 | 說明 |
|---|---|---|
| 依靜音切檔 | 否 | 只看有聲／無聲；例外：有背景音樂會切不開 |
| 語音辨識 | 是 | 英文、國語、日文好；台語、客語弱 |
| 對應單字表 | 部分 | 國語同音字、單一個字較易對錯 |
| Mac `say` 合成 | 是 | 英文、國語（台灣）、粵語、日文有內建語音；台語無 |
| 打包、播放 | 否 | 對筆來說聲音就是聲音 |

**需特別注意的內容**：注音與自然發音（太短，辨識不出）、中英混念、兒歌與唱的內容。

**備案：照順序對應**。語音辨識失靈時，切出的第 1 段對第 1 張內容貼、第 2 段對第 2 張……只要錄音順序與貼紙順序一致即可，任何語言都適用。此時語音辨識只用來檢查。

## 6. 音檔來源（支援的輸入情境）

| 來源 | 情境 | 處理方式 |
|---|---|---|
| 切現成音檔 | 書附 CD／MP3，但一軌一整段 | 走完整流程 ①～⑤ |
| 自己錄 | 書沒有音檔，錄成一整段 | 同上 |
| Mac 語音合成 | 單字卡、簡單句子 | 給單字清單，`say` 批次產生，跳過 ①② |
| 錄音貼 | 不想用電腦 | 不需要本 Skill，直接用筆錄 |

## 7. 已知的卡米規則（來自 AP4 → DAB 專案實測）

- 卡米先靠「入口碼」選書，再對內文碼；未選書直接點內容會說「不對應的文件」
- 入口碼 60001–65000：檔名前綴取末四碼（例：60309 → `0309-…dab`）
- 智能書名貼 001 對應檔名前綴 `001-`（已實測）
- 普通書名貼用 `001-` 前綴**沒有反應**，命名規則待查（可能是 `001-1-` 之類）
- DAB 格式支援任意碼號（上限 65535），檔頭兩塊不透明資料可原樣沿用，卡米不驗證

## 9. 實作順序建議

1. 確認第 8 節的碼號規則（需實體貼紙報碼）
2. 先做 `split.py` + `review.py`，拿一段真實音檔測試切檔品質
3. 加入 `transcribe.py`，評估辨識準確度
4. 做 `assign.py`（先做「照順序對應」，再做「單字表比對」）
5. 串接 `dab_tool.py`，產出第一本 DIY 點讀包並上筆實測
6. 撰寫 `SKILL.md`，整理成正式 Skill
