## 遷移動機

GitHub Copilot CLI（`copilot`）的免費額度有限且模型選擇受 GitHub 訂閱方案限制。**OpenCode CLI**（`opencode`）提供多個免費模型（`opencode/*` 系列），同時也能透過 `github-copilot/*` provider 存取 Copilot 模型，形成一個**統一的 CLI 介面**管理兩套模型來源。

核心優勢：
1. **免費模型池**：`opencode/*` 系列模型完全免費，可吸收低複雜度任務的成本
2. **統一指令介面**：`opencode run -m {provider/model}` 統一存取 OpenCode 原生模型與 GitHub Copilot 模型
3. **更多模型選擇**：從 Copilot 的固定幾個模型擴展到 5+ 個免費模型 + Copilot 全線模型

## 變更一：Copilot Tier 系統更新

### 現狀（v4.2）

| Tier | Developer 模型 | 來源 |
|---|---|---|
| `FREE` | gpt-5-mini | Copilot CLI |
| `LOW` | gpt-5.4-mini | Copilot CLI |
| `STANDARD` | claude-sonnet-4.6 | Claude Code（native） |
| `COMPLEX` | gpt-5.3-codex | Copilot CLI |

### v4.4 提案：OpenCode 取代 Copilot CLI

| Tier | Developer 模型（主力） | 備選模型 | 來源 | 備註 |
|---|---|---|---|---|
| `FREE` | `opencode/deepseek-v4-flash-free` | opencode/* 免費池 | OpenCode（免費） | 完全免費，取代 gpt-5-mini |
| `LOW` | `github-copilot/gpt-5-mini` | `github-copilot/mai-code-1-flash-picker`、`github-copilot/gemini-3.5-flash` | OpenCode → Copilot | gpt-5-mini 最便宜；mai-code 同價程式碼專用；gemini-3.5-flash 推理較強 |
| `STANDARD` | claude-sonnet-4.6 | — | Claude Code（native） | 不變 |
| `COMPLEX` | `github-copilot/gpt-5.3-codex` | — | OpenCode → Copilot | 透過 OpenCode 統一介面 |

**LOW Tier 模型成本比較：**

| 模型 | 輸入 | 輸出 | 特性 |
|---|--:|--:|---|
| `github-copilot/gpt-5-mini` | 25 | 200 | 最低成本 |
| `github-copilot/mai-code-1-flash-picker` | 75 | 450 | 同 gpt-5.4-mini 價位，程式碼專用 |
| `github-copilot/gemini-3.5-flash` | 150 | 900 | 推理較強，適合中等複雜任務 |

> Credits/M（1 Credit = US$0.01）

**核心優勢：** FREE tier 從 Copilot 付費配額切換到完全免費的 OpenCode 模型，`--economy` 模式零成本。

### 免費模型 Fallback Chain（FREE tier）

```

  → opencode/north-mini-code-free
  → opencode/mimo-v2.5-free
```

5 個免費模型的 fallback chain，大幅提升 FREE tier 的可用性。

### LOW Tier Fallback Chain

## 變更二：CLI 指令更新

### 舊指令（Copilot CLI）

```bash
# Developer
copilot --model gpt-5.4-mini -p "Implement the following task..." 2>&1

# Reviewer
cat $REVIEW_FILE | copilot --model gpt-4.1 \
  -p "Review this code..." 2>&1
```

### 新指令（OpenCode CLI）

```bash
# Developer（FREE tier）
opencode run -m opencode/deepseek-v4-flash-free \
  "Implement the following task..." 2>&1

# Developer（LOW tier，透過 Copilot provider）
opencode run -m github-copilot/gpt-5-mini \
  "Implement the following task..." 2>&1

# Reviewer
cat $REVIEW_FILE | opencode run -m github-copilot/gpt-5-mini \
  "Review this code for spec compliance...
   Output ONLY in this exact format:
   SRC:opencode/gpt-5-mini
   C|{file:line_or_NA}|{issue}|{fix}
   VERDICT:PASS or VERDICT:WARN or VERDICT:BLOCK" 2>&1
```

**注意：**
- `SRC:` 欄位更新為 `SRC:opencode/{model-slug}`
- 指令格式從 `copilot --model {model} -p "..."` 改為 `opencode run -m {provider/model} "..."`
- stdin pipe 行為需驗證（`cat file | opencode run -m ...`）

## 變更四：錯誤處理更新

### 新錯誤處理（v4.4）

```
Exit code 1 + "model not found" / "unknown model"  → ERR:MODEL, try next in fallback
Exit code 1 + "quota" / "429" / "rate limit"        → ERR:QUOTA, try next provider
Exit code 1 + "401" / "Unauthorized"                → ERR:AUTH
Timeout（無輸出）                                    → ERR:TIMEOUT, retry once
"command not found: opencode"                        → ERR:CLI_MISSING
```

### Provider 層級 Fallback（新概念）

```
opencode/* 模型失敗
  → 嘗試下一個 opencode/* 免費模型
  → 全部失敗 → 嘗試 github-copilot/* 模型
  → 全部失敗 → SKIP

github-copilot/* 模型失敗
  → 嘗試下一個 github-copilot/* 模型
  → 全部失敗 → 降級到 opencode/* 免費模型
  → 全部失敗 → SKIP
```

## 變更五：角色名稱決策

### 方案 A：保留 `copilot-developer` / `copilot-reviewer` 名稱（建議）

理由：
- 角色名稱代表「負責開發 / 審查的角色視角」，與底層 CLI 無關（同 v4.3 中 `gemini-reviewer` 保留的邏輯）
- 修改角色名稱會影響 `reviewer_set` 快取鍵值（`{copilot,claude,gemini}`），造成既有快取失效
- Team Lead Translation Layer 的輸出標題維持一致

### 方案 B：改名為 `opencode-developer` / `opencode-reviewer`

- 更直覺對應底層 CLI
- 但破壞性較高，需同步修改所有快取鍵值

**建議：** 採方案 A，保留現有角色名稱。
