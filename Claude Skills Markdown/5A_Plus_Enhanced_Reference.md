# 5A+ 方法論參考指南 (增強版)

## 框架概述

5A+ 是一個**從想法到落地的完整循環方法論**,源自 MAPS 系統化思維的實踐層 (S - Systems)。

**核心循環**: `AIM → ACQUIRE → ATTEMPT → ADJUST → APPLY → + (PLUS)`

- **A1 (AIM)** - 明確目標: 評估價值,定義目標
- **A2 (ACQUIRE)** - 獲取資源: 收集資料,學習準備
- **A3 (ATTEMPT)** - 快速驗證: MVP 實踐,小步快跑
- **A4 (ADJUST)** - 評估迭代: 數據分析,優化改進
- **A5 (APPLY)** - 規模化: 擴展場景,團隊共享
- **+ (PLUS)** - 持續優化: 監控運營,知識沉澱

**與 MAPS 的關係**: 5A+ 是 MAPS 中 S (Systems) 層的具體實踐方法論

**與 SCQA 的關係**: SCQA 幫助表達每個 A 階段的成果和決策

## 一、A1 (AIM) - 明確目標

### 目的
評估任務是否值得做,定義清晰的目標和成功標準

### 核心問題

```markdown
## A1 - 目標定義

### 三個關鍵問題

**問題 1: 這個任務值得做成資產嗎?**
- [ ] 是否會重複使用? (頻率 ≥ 3次/週)
- [ ] 是否需要專業判斷? (有隱性知識)
- [ ] 是否耗時但可標準化? (SOP 清晰)

**問題 2: 我們要達成什麼目標?**
- 當前狀態: [具體描述]
- 期望狀態: [具體描述]
- 成功標準: [可量化指標]

**問題 3: 為什麼是現在?**
- 機會窗口: [時間限制]
- 成本效益: [投入產出比]
- 風險評估: [不做的後果]
```

### 評估框架

#### 框架 1: 資產化價值評估

```markdown
## 資產化價值計算

**公式**: 
資產化價值 = 頻率 × 耗時 × 複雜度係數

**評分標準**:

**頻率評分** (1-10):
- 每天多次: 10分
- 每天1次: 8分
- 每週3-5次: 6分
- 每週1-2次: 4分
- 每月數次: 2分
- 偶爾使用: 1分

**耗時評分** (1-10):
- 4小時以上: 10分
- 2-4小時: 8分
- 1-2小時: 6分
- 30分鐘-1小時: 4分
- 10-30分鐘: 2分
- 10分鐘以內: 1分

**複雜度係數** (1.0-3.0):
- 需要多層判斷邏輯: 3.0
- 需要專業知識: 2.5
- 有標準流程但繁瑣: 2.0
- 簡單重複性任務: 1.5
- 基本操作: 1.0

**決策標準**:
- ≥ 150分: 🔥🔥🔥 最高優先級,立即開始
- 100-149分: 🔥🔥 高優先級,本週啟動
- 50-99分: 🔥 中優先級,排入計劃
- 20-49分: ⏸️ 低優先級,資源充裕時考慮
- < 20分: ❌ 不建議資產化,直接執行即可

**範例計算**:
任務: 整理學習筆記
- 頻率: 每週5次 = 6分
- 耗時: 每次2小時 = 8分
- 複雜度: 需要多層判斷 = 3.0
- 總分: 6 × 8 × 3.0 = 144分
- 結論: 🔥🔥 高優先級,值得做成 Skill
```

### 資源獲取策略

#### 策略 1: 80/20 原則

```markdown
## 80/20 學習策略

**目標**: 用 20% 的時間掌握 80% 的必需知識

**第一步: 識別核心知識**
問自己:
- 最低限度需要知道什麼才能開始?
- 哪些是「好奇想知道」vs「必須知道」?
- 哪些可以邊做邊學?

**第二步: 快速學習路徑**
優先順序:
1. 官方文檔的「快速開始」部分
2. 社群中的「最常見問題」
3. 2-3 個高質量教程
4. 1-2 個實際案例分析

**第三步: 設置時間盒**
- 文檔閱讀: 不超過 2 小時
- 教程學習: 不超過 3 小時
- 案例研究: 不超過 2 小時
- 總計: 1 天內完成

**避免陷阱**:
❌ 想讀完所有文檔再開始
❌ 追求完全理解每個細節
❌ 陷入無盡的教程循環

✅ 快速瀏覽,抓住核心
✅ 帶著問題學習
✅ 邊學邊實踐
```

## 三、A3 (ATTEMPT) - 快速驗證

### 目的
創建 MVP (Minimum Viable Product/Skill),快速驗證想法是否可行

### 核心原則

```markdown
## A3 - MVP 原則

### MVP 的定義
**不是**: 功能閹割的完整產品
**而是**: 能驗證核心假設的最小實驗

### 三個關鍵原則

**原則 1: 最小功能集**
只做核心功能,暫時忽略:
- 完整的錯誤處理
- 漂亮的界面/格式
- 性能優化
- 邊界情況
- 擴展功能

**原則 2: 時間盒限制**
- 簡單任務: 2-4 小時
- 中等任務: 1-2 天
- 複雜任務: 不超過 1 週

超過時間盒就要重新評估

**原則 3: 可驗證假設**
MVP 必須能回答:
- 這個方法可行嗎?
- 能達到預期效果嗎?
- 有沒有重大障礙?
```

### MVP 設計框架

#### 框架 1: MVS (Minimum Viable Skill)

```markdown
## MVS 設計模板

### 核心功能定義
**完整功能清單**:
1. 功能 A - [描述]
2. 功能 B - [描述]
3. 功能 C - [描述]
4. 功能 D - [描述]
5. 功能 E - [描述]

**MVS 只包含**:
- ✅ 功能 A (最核心)
- ✅ 功能 B (必需)
- ⏸️ 功能 C (v2.0)
- ⏸️ 功能 D (v2.0)
- ⏸️ 功能 E (如果需要)

**功能簡化策略**:
| 完整功能 | MVS 簡化版 | 為什麼簡化 |
|---------|-----------|----------|
| 多層判斷 | 2 層判斷 | 驗證核心邏輯即可 |
| 完整格式 | Markdown | 先保證可用性 |
| 複雜驗證 | 基本檢查 | 手動補充驗證 |
| 錯誤處理 | 基本提示 | v2.0 再完善 |

### 簡化範例

**完整版 Skill**:
```
- 4 層判斷邏輯
- 10 個輸出字段
- 完整錯誤處理
- 多種輸出格式
- 自動化驗證
預估時間: 40 小時
```

**MVS 版本**:
```
- 2 層核心判斷
- 5 個關鍵字段
- 基本錯誤提示
- Markdown 格式
- 人工驗證結果
實際時間: 4 小時
```

**MVS 驗證目標**:
- [ ] 核心判斷邏輯是否有效
- [ ] 輸出格式是否可讀
- [ ] 整體流程是否順暢
- [ ] 是否值得繼續投入
```

```markdown
  - 演示視頻 (5分鐘)
  - Workshop 材料
  - 使用範例集

□ **支持計劃**
  - 指定負責人
  - 建立支持渠道
  - 定義響應時間 SLA

### 規模化檢查點

**準備就緒**:
- [ ] 文檔完整
- [ ] 試點成功 (2-3 人試用無重大問題)
- [ ] 有支持資源
- [ ] 獲得管理層支持 (如需要)

**推廣標準**:
- [ ] 穩定性 ≥ 95% (很少出錯)
- [ ] 文檔完整性 ≥ 90% (很少需要口頭解釋)
- [ ] 易用性得分 ≥ 7/10
- [ ] 有成功案例可展示

**撤退條件**:
- [ ] 試點失敗 (2-3 人試用都有重大問題)
- [ ] 維護成本過高
- [ ] 用戶接受度低
- [ ] 有更好的替代方案
```

### A5 常見陷阱

```markdown
## 陷阱 1: 過早推廣

❌ 錯誤:
"MVP 剛做出來,
還有一堆 Bug,
但我立即推廣給全公司"

(導致負面第一印象)

✅ 正確:
"先小範圍試點 2-3 人,
收集反饋修復問題,
穩定後再逐步推廣"

要點:
- 試點 → 優化 → 推廣
- 保護第一印象
- 小步快跑

## 陷阱 2: 文檔不足

❌ 錯誤:
"我口頭告訴大家怎麼用,
不用寫文檔了"

(無法規模化)

✅ 正確:
"我寫了完整的文檔,
包括快速開始、詳細說明、
常見問題,新人可以自助學習"

要點:
- 文檔是規模化的基礎
- 減少重複解釋
- 讓新人自助學習

## 陷阱 3: 缺乏支持

❌ 錯誤:
"我推廣出去就不管了,
有問題他們自己解決"

(導致棄用)

✅ 正確:
"我建立了 Slack 頻道,
指定自己為負責人,
承諾 24 小時內響應問題"

要點:
- 建立支持渠道
- 指定負責人
- 定義響應時間
```

## 5A+ 與其他框架的結合

### 5A+ × SCQA

```markdown
每個 A 階段都可以用 SCQA 表達:

**A1 (AIM)**:
- S: 當前如何完成任務
- C: 為什麼需要改變
- Q: 我們要達成什麼目標
- A: 目標定義和成功標準

**A2 (ACQUIRE)**:
- S: 已有資源狀況
- C: 資源缺口
- Q: 如何高效獲取
- A: 獲取計劃

**A3 (ATTEMPT)**:
- S: MVP 範圍
- C: 需要驗證的問題
- Q: 驗證問題
- A: 測試用例和結果

**A4 (ADJUST)**:
- S: 當前表現
- C: 發現的問題
- Q: 優化目標
- A: 優化方案

**A5 (APPLY)**:
- S: 當前能力邊界
- C: 擴展機會
- Q: 如何規模化
- A: 擴展和推廣計劃
```

### 5A+ × TBRC

```markdown
TBRC 用於組織每個 A 階段的文檔:

**T (Thesis)**:
- 定義每個階段的核心論點
- 說明為什麼這個階段重要

**B (Boundary)**:
- 明確每個階段的範圍
- 定義什麼在內什麼在外

**R (Racetrack)**:
- 提供分層的實踐指南
- R1-R4 漸進式展開

**C (Closure)**:
- 總結階段交付物
- 提供下一步行動清單
```

```markdown
- 影響 A1: 評估是否值得做成資產
```

## 快速參考卡

```
5A+ 循環:
A1 (AIM)     → 評估價值,定義目標 (資產化價值 ≥50分)
A2 (ACQUIRE) → 快速學習,準備資源 (80/20原則,<1天)
A3 (ATTEMPT) → 創建 MVP,快速驗證 (時間盒 <1週)
A4 (ADJUST)  → 數據驅動,迭代優化 (綜合得分 ≥7/10)
A5 (APPLY)   → 擴展場景,團隊共享 (文檔+試點+推廣)
+  (PLUS)    → 持續運營,知識沉澱 (週/月/季回顧)

關鍵原則:
✅ 小步快跑,快速迭代
✅ 數據驅動,而非憑感覺
✅ 時間盒管理,避免完美主義
✅ 先 MVS,再完善
✅ 持續優化,而非一次完美

常見陷阱:
❌ 目標過於宏大 (A1)
❌ 過度準備學習 (A2)
❌ MVP 不夠 M (A3)
❌ 追求完美主義 (A4)
❌ 過早推廣 (A5)
❌ 缺乏持續運營 (Plus)
```
