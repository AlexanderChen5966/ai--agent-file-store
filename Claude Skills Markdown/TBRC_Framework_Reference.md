# TBRC 框架參考指南

## 框架概述

TBRC 是一個用於**結構化知識組織**的內容框架,將複雜主題拆解為四個層次:

- **T (Thesis)** - 論點核心: 提煉核心觀點與本質定義
- **B (Boundary)** - 邊界定義: 明確適用範圍與限制條件
- **R (Racetrack)** - 實踐路徑: 分層的可執行步驟
- **C (Closure)** - 總結收攏: 整合要點與行動指南

---

## 一、T (Thesis) - 論點核心

### 目的
建立認知錨點,定義問題本質

### 結構模板

```markdown
## T - 核心論點

### T1: 本質定義
[用一句話定義這個主題的核心是什麼]

### T2: 核心價值  
[為什麼這個主題重要?解決什麼問題?]

### T3: 關鍵洞察
[3-5 個經過驗證的核心觀點]

#### 洞察 1: [標題]
**論點**: [清晰陳述]
**驗證**: ✅已驗證 / ⚠️待驗證 / ❌可疑
**來源**: [官方文檔/實踐經驗/專家意見]
**重要性**: ⭐⭐⭐⭐⭐ (5星評分)

#### 洞察 2: [標題]
[同上結構]
```

### 質量標準
- ✅ 每個論點都有明確來源
- ✅ 可信度標記清晰
- ✅ 價值評級有依據
- ❌ 避免模糊或主觀的陳述

---

## 二、B (Boundary) - 邊界定義

### 目的
明確適用場景與限制條件,避免誤用

### 結構模板

```markdown
## B - 邊界與範圍

### B1: 適用場景 ✅
**最佳用途**:
- 場景 1: [具體描述]
- 場景 2: [具體描述]
- 場景 3: [具體描述]

**輸入要求**:
- 格式: [如 SRT, Markdown, JSON]
- 大小: [如 <10MB, 100-1000 行]
- 質量: [如 需人工預處理]

**輸出承諾**:
- 格式: [如 Markdown, PDF]
- 質量: [如 可直接發布, 需人工審校]
- 時間: [如 5分鐘內, 取決於大小]

### B2: 限制條件 ⚠️
**技術限制**:
- 依賴: [如 僅 Claude Code, 需 MCP]
- 容量: [如 上下文窗口限制]
- 兼容: [如 不支持某些格式]

**使用限制**:
- 權限: [如 需 Pro 帳戶]
- 環境: [如 需網絡連接]
- 頻率: [如 每小時最多 X 次]

### B3: 不適用場景 ❌
**明確排除**:
- ❌ 場景 1: [為什麼不適合]
- ❌ 場景 2: [為什麼不適合]
- ❌ 場景 3: [為什麼不適合]

**替代方案**:
- 對於場景 X → 建議使用 [其他工具/方法]
```

### 質量標準
- ✅ 邊界清晰可判斷
- ✅ 提供替代方案
- ✅ 限制條件具體
- ❌ 避免「可能」「也許」等模糊詞

### 目的
提供分層的、可執行的實踐指南

### 四層結構

#### R1: 理解對比層

```markdown

| 功能性 | [描述] | [描述] | [描述] |
| 成本 | [描述] | [描述] | [描述] |

### 核心差異
**本方案的獨特價值**:
1. [差異點 1]
2. [差異點 2]
3. [差異點 3]

**權衡取捨**:
- 優勢: [列舉]
```

```
### 核心組件說明

- 職責: [單一職責描述]

### 數據流設計
```


## 使用 TBRC 框架的檢查清單

### 創建內容時

- [ ] **T - 論點**: 核心觀點是否清晰且有依據?
- [ ] **B - 邊界**: 適用範圍與限制是否明確?
- [ ] **R - 路徑**: 是否提供了分層的實踐指南?
- [ ] **C - 收攏**: 是否有可執行的行動清單?

### 質量檢查

- [ ] 每個部分都有具體的內容(不是空框架)
- [ ] 避免使用模糊詞彙("可能"、"也許"、"大概")
- [ ] 提供了具體的例子或數據支持
- [ ] 標記了可信度和重要性等級
- [ ] 包含了失敗案例或常見陷阱

### 可讀性檢查

- [ ] 使用了恰當的表情符號和標記(✅❌⚠️⭐)
- [ ] 分層清晰,不超過 3 層縮進
- [ ] 每個段落有明確的小標題
- [ ] 使用了表格、代碼塊等格式化工具
- [ ] 關鍵信息用**粗體**標記

## TBRC 框架的四層判斷邏輯

在處理內容時,可以套用以下判斷標準:

### 1. 價值判斷 (Value Assessment)
- ⭐⭐⭐⭐⭐ 核心洞察 - 必須包含在 T
- ⭐⭐⭐⭐ 重要補充 - 應包含在 R1-R2
- ⭐⭐⭐ 有用信息 - 可包含在 R3-R4
- ⭐⭐ 參考資料 - 放入 C3 資源
- ⭐ 次要內容 - 可以省略

### 2. 可信度判斷 (Credibility Check)
- ✅ 已驗證 - 有官方文檔或數據支持
- ⚠️ 待驗證 - 合理推斷但缺乏證據
- ❌ 可疑 - 與已知事實矛盾或來源不明

### 3. 提取粒度 (Granularity)
- 🔥 核心內容 - 直接引用或詳細展開
- 📝 改寫提煉 - 用自己的話重述
- 🗂️ 歸類打標 - 只記錄主題或鏈接

### 4. 放置位置 (Placement)
- T 層: 核心論點、本質定義
- B 層: 邊界條件、限制說明
- R 層: 實踐指南、操作步驟
- C 層: 總結要點、行動清單

## 常見錯誤與改進

### ❌ 錯誤示範

**論點模糊**:
```markdown
## T - 核心論點
這個工具很好用,可以提高效率。
```

**邊界不清**:
```markdown
## B - 邊界
適用於大部分場景。
```

**路徑空洞**:
```markdown
## R - 實踐路徑
1. 開始使用
2. 完成任務
```

### ✅ 正確示範

**論點清晰**:
```markdown
## T - 核心論點
### T1: 本質定義
Claude Skills 是將判斷邏輯封裝為可復用模塊的架構模式。

### T2: 核心價值
解決問題: 避免每次重寫 Prompt,實現知識資產化
關鍵指標: 5 分鐘完成原本 3-4 小時的工作

### T3: 關鍵洞察
**洞察 1: 漸進式披露機制**
論點: 啟動時只加載 name + description (~100 tokens)
驗證: ✅ 官方工程博客確認
重要性: ⭐⭐⭐⭐⭐
```

**邊界明確**:
```markdown
## B - 邊界
### B1: 適用場景 ✅
- 重複性任務 (每週 3+ 次)
- 需要專業判斷 (有隱性知識)
- 耗時但標準化 (SOP 清晰)

### B3: 不適用場景 ❌
- ❌ 一次性任務 → 直接用 Prompt
- ❌ 高度創意工作 → 無法標準化
- ❌ 場景差異大 → 無固定流程
```

**路徑具體**:
```markdown
## R3 - 實踐場景
### 場景 1: 整理學習筆記

**執行步驟**:
1. **準備階段**
   - [ ] 確認筆記格式為 Markdown
   - [ ] 文件大小 < 50KB
   - [ ] 已安裝 discussion-organizer Skill

2. **執行階段**
   ```
   輸入: "整理這些筆記" + 上傳文件
   Claude 自動觸發 discussion-organizer
   執行四層判斷邏輯:
   ├─ 價值評估 (⭐評分)
   ├─ 可信度檢查 (✅⚠️❌)
   ├─ 提取粒度 (🔥📝🗂️)
   └─ 措辭規範化
   輸出: 結構化的 TBRC 格式筆記
   ```

3. **驗證階段**
   - [ ] 檢查是否包含 T/B/R/C 四部分
   - [ ] 驗證可信度標記正確
   - [ ] 確認無遺漏核心信息

**預期結果**:
- ✅ 成功: 5 分鐘生成結構化筆記
- ⚠️ 部分成功: 需手動調整個別分類
- ❌ 失敗: 檢查文件格式或 Skill 安裝
```

## 快速參考卡

```
T (Thesis)     → 是什麼? 為什麼重要?
B (Boundary)   → 適用於? 不適用於?
R (Racetrack)  → 怎麼做? 分幾步?
C (Closure)    → 關鍵點? 下一步?

判斷標準:
⭐⭐⭐⭐⭐ → T 層
✅已驗證 → 高可信
🔥核心 → 詳細展開
📝改寫 → 精簡表達
```
