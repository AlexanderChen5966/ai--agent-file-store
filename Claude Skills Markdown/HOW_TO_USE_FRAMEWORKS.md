# 如何使用 TBRC 和 MAPS 框架生成 Claude Skills

## 快速開始

當你需要創建一個 Claude Skill 時,可以這樣使用這兩個參考文件:

### 方式 1: 直接引用 (推薦用於簡單 Skill)

```
我要創建一個 [功能描述] 的 Skill。

請參考以下框架:
- TBRC_Framework_Reference.md - 用於內容組織
- MAPS_Methodology_Reference.md - 用於系統化設計

按照以下步驟:
1. 用 MAPS 的 5A+ 流程評估和規劃
2. 用 TBRC 結構組織 Skill 的文檔和參考資料
3. 生成完整的 SKILL.md 文件

我的需求: [詳細描述你的需求]
```

### 方式 2: 分步驟引用 (推薦用於複雜 Skill)

#### 步驟 1: 評估階段 (使用 MAPS - A1)

```
參考 MAPS_Methodology_Reference.md 中的 "A1: AIM - 明確目標" 部分。

幫我評估以下任務是否值得做成 Skill:
- 任務: [描述]
- 頻率: [每週 X 次]
- 耗時: [每次 X 分鐘]
- 判斷複雜度: [簡單/中等/複雜]

使用資產化價值評估框架給出建議。
```

#### 步驟 2: 架構設計 (使用 MAPS - A)

```
參考 MAPS_Methodology_Reference.md 中的 "二、A (Architecture)" 部分。

根據我的需求,幫我選擇合適的架構模式:
- 需求: [描述]
- 是否需要多個步驟: [是/否]
- 是否需要獨立上下文: [是/否]
- 是否有複雜判斷邏輯: [是/否]

使用架構決策矩陣給出建議,並繪製數據流圖。
```

#### 步驟 3: Prompt 設計 (使用 MAPS - P)

```
參考 MAPS_Methodology_Reference.md 中的 "三、P (Prompt)" 部分。

幫我設計 SKILL.md 的核心 Prompt:
- 角色定義: [Skill 要扮演什麼角色]
- 工作流程: [需要哪幾個階段]
- 判斷邏輯: [需要什麼判斷標準]
- 輸出規範: [期望的輸出格式]

使用 Prompt 工程模板生成完整的 SKILL.md。
```

#### 步驟 4: 內容組織 (使用 TBRC)

```
參考 TBRC_Framework_Reference.md。

幫我用 TBRC 框架組織 Skill 的參考文檔:
- T: [核心論點] - 這個 Skill 解決什麼問題
- B: [邊界定義] - 適用和不適用的場景
- R: [實踐路徑] - 分層的使用指南
- C: [總結收攏] - 快速參考和行動清單

生成 references/sop.md 文件。
```

#### 步驟 5: 系統落地 (使用 MAPS - S)

```
參考 MAPS_Methodology_Reference.md 中的 "四、S (Systems)" 部分。

幫我制定這個 Skill 的:
- MVP 範圍: [最小功能集]
- 測試計劃: [3 個測試用例]
- 優化指標: [觸發準確率、執行成功率、Token 消耗]
- 推廣計劃: [如何分享給團隊]

使用 5A+ 流程生成完整的實施計劃。
```

## 完整範例

### 需求: 創建一個整理學習筆記的 Skill

#### 第一次對話: 評估和規劃

```
我要創建一個整理學習筆記的 Skill。

參考文件:
- TBRC_Framework_Reference.md
- MAPS_Methodology_Reference.md

需求描述:
我經常閱讀技術文章和參加線上課程,會記錄很多碎片化的筆記。這些筆記包括:
- 核心概念的摘錄
- 個人的理解和思考
- 未驗證的觀點
- 需要進一步學習的主題

現狀問題:
- 筆記雜亂無章,難以回顧
- 不知道哪些是已驗證的事實,哪些是個人猜測
- 缺乏結構,找不到重點
- 每次整理要花 2-3 小時

期望結果:
- 自動分類:核心知識、實踐經驗、待驗證內容
- 可信度標記:區分事實、觀點、推測
- 結構化輸出:按 TBRC 框架組織
- 時間節省:從 2-3 小時縮短到 10 分鐘內

請使用 MAPS 方法論幫我:
1. 評估這個任務的資產化價值
2. 選擇合適的架構模式
3. 設計 MVP 範圍
```

**AI 的回應會包括**:
- 資產化價值評估 (分數和優先級)
- 架構選型建議 (能力包型 Skill)
- MVP 功能範圍 (核心判斷邏輯)
- 數據流設計

#### 第二次對話: 生成 SKILL.md

```
很好!現在請幫我生成完整的 SKILL.md 文件。

參考 MAPS_Methodology_Reference.md 中的:
- "模板 1: SKILL.md 的 Prompt 結構"

要求:
1. 封裝四層判斷邏輯:
   - 價值判斷 (⭐評分)
   - 可信度判斷 (✅⚠️❌標記)
   - 提取粒度 (🔥📝🗂️)
   - 措辭規範化

2. 輸出格式:
   - 按 TBRC 框架組織
   - Markdown 格式
   - 包含表情符號標記

3. 處理流程:
   - 讀取筆記文件
   - 逐條分析和評估
   - 分類和重組
   - 生成結構化輸出

請生成完整的 SKILL.md 內容。
```

#### 第三次對話: 生成參考文檔

```
現在請幫我生成 references/sop.md 文件。

參考 TBRC_Framework_Reference.md 的完整結構。

內容包括:
- T: 筆記整理的核心價值和方法論
- B: 適用的筆記類型和不適用的場景
- R: 四層判斷邏輯的詳細說明和示例
- C: 快速使用指南和常見問題

請生成完整的 sop.md 內容。
```

#### 第四次對話: 生成測試計劃

```
最後,請幫我生成測試計劃和優化方案。

參考 MAPS_Methodology_Reference.md 中的:
- "A3: ATTEMPT - 快速驗證"
- "A4: ADJUST - 評估迭代"

包括:
1. 3 個測試用例 (正常、邊界、異常)
2. 質量評估指標
3. 優化迭代計劃
4. 團隊推廣策略

請生成完整的測試和優化文檔。
```

## 使用技巧

### 技巧 1: 漸進式生成

不要一次性要求生成所有內容,而是:
1. 先評估和規劃
2. 再生成核心文件
3. 然後補充參考資料
4. 最後完善測試和文檔

### 技巧 2: 引用具體章節

明確指出要參考哪個框架的哪個部分:
- ✅ "參考 MAPS 的 A1 部分..."
- ✅ "使用 TBRC 的 R3 層結構..."
- ❌ "參考那兩個文件..."

### 技巧 3: 提供具體需求

越具體越好:
- ✅ "每週使用 5 次,每次 30 分鐘"
- ✅ "需要判斷內容的可信度和重要性"
- ❌ "幫我做個筆記工具"

### 技巧 4: 要求結構化輸出

明確要求 AI 使用框架中的模板:
- ✅ "使用 SKILL.md Prompt 結構模板"
- ✅ "按照 TBRC 四層結構組織"
- ❌ "隨便寫一下就好"

### 技巧 5: 迭代優化

第一版不完美沒關係:
```
根據我的反饋修改:
1. 描述詞不夠具體,增加觸發詞: [列表]
2. 判斷邏輯 X 需要補充 [具體標準]
3. 輸出格式改為 [新格式]
```

## 常見場景範例

### 場景 1: 文檔處理類 Skill

```
需求: 把字幕文件轉換成文章

使用框架:
- MAPS-A: 選擇軟編排架構 (多階段處理)
- MAPS-P: 設計每個階段的 Subagent
- TBRC: 組織最佳實踐文檔

關鍵點:
- 文件傳遞上下文 (不佔用主上下文)
- 條件分支 (檢測語言決定是否翻譯)
- 錯誤處理 (每階段驗證輸出)
```

### 場景 2: 判斷分析類 Skill

```
需求: 審核文章質量

使用框架:
- MAPS-A: 選擇能力包架構 (封裝判斷邏輯)
- MAPS-P: 設計多維度判斷標準
- TBRC: 組織審核標準和示例

關鍵點:
- 多層判斷 (語法、邏輯、風格、專業性)
- 可信度標記 (事實 vs 觀點)
- 優先級排序 (嚴重性評估)
```

### 場景 3: 數據處理類 Skill

```
需求: 處理和分析 CSV 數據

使用框架:
- MAPS-A: 選擇編排架構 + MCP 工具
- MAPS-P: 設計數據驗證和轉換邏輯
- TBRC: 組織數據格式規範

關鍵點:
- 輸入驗證 (格式、完整性、範圍)
- 異常處理 (缺失值、異常值)
- 結構化輸出 (統一格式)
```

### 場景 4: 工作流編排類 Skill

```
需求: 自動化內容發布流程

使用框架:
- MAPS-A: 選擇軟編排 + 硬編排 (Make)
- MAPS-S: 設計完整的 5A+ 流程
- TBRC: 組織每個環節的 SOP

關鍵點:
- 跨平台協作 (Claude + Make + MCP)
- 狀態管理 (追蹤發布進度)
- 回滾機制 (失敗恢復)
```

## 故障排除

### 問題 1: 生成的 Skill 太簡單

**症狀**: 只有基本框架,沒有具體內容

**原因**: 需求描述不夠具體

**解決**:
```
請補充以下細節:
1. 具體的判斷標準和示例
2. 輸入輸出的完整範例
3. 異常情況的處理邏輯
4. 引用 [框架中的具體章節]
```

### 問題 2: 生成的內容不符合框架

**症狀**: 結構混亂,不遵循 TBRC 或 MAPS

**原因**: 沒有明確要求使用特定模板

**解決**:
```
請嚴格按照以下模板重新生成:
- TBRC_Framework_Reference.md 中的 [具體模板]
- MAPS_Methodology_Reference.md 中的 [具體模板]

要求:
1. 保持模板結構不變
2. 填入我的具體內容
3. 使用框架中的標記符號
```

### 問題 3: 內容太長,不實用

**症狀**: 生成了幾千行的文檔

**原因**: 沒有明確 MVP 範圍

**解決**:
```
請簡化為 MVP 版本:
1. SKILL.md: 200-400 行
2. 只包含核心判斷邏輯
3. 複雜內容放 references/
4. 參考 MAPS 的 A3 部分 (快速驗證)
```

### 問題 4: 觸發不準確

**症狀**: Claude 不觸發或錯誤觸發

**原因**: description 寫得不好

**解決**:
```
請優化 description,參考 TBRC 的描述優化章節:
1. 添加常用觸發詞: [列表]
2. 明確輸入類型: [格式]
3. 強調特殊能力: [列表]
4. 添加排除詞: 不適用於 [場景]
```

## 進階用法

### 用法 1: 組合多個 Skills

```
我要創建一個工作流,組合以下 Skills:
- Skill A: [功能]
- Skill B: [功能]
- Skill C: [功能]

參考 MAPS 的軟編排架構,幫我設計:
1. 主 Skill 的 SOP 定義
2. 數據傳遞方案 (文件格式)
3. 失敗處理邏輯
4. 整體數據流圖
```

### 用法 2: 與 MCP 集成

```
我要增強現有 Skill,集成 [MCP 名稱]。

參考 MAPS 的架構擴展部分,幫我:
1. 評估集成價值
2. 設計集成方案
3. 更新 allowed-tools
4. 修改工作流程
5. 更新文檔說明
```

### 用法 3: 團隊協作開發

```
我們團隊要共同開發一個 Skill。

參考 MAPS 的系統化部分,幫我制定:
1. 開發規範 (命名、結構、文檔)
2. 協作流程 (Git workflow)
3. 測試策略 (單元測試、集成測試)
4. 部署方案 (版本管理、發布流程)
5. 培訓計劃 (文檔、演示、支持)
```

### 用法 4: 建立 Skills 生態

```
我要建立一個 Skills 資產庫。

參考 MAPS 的完整體系,幫我設計:
1. Notion 資產庫結構
2. Skills 分類體系
3. 依賴關係管理
4. 使用數據追蹤
5. 優化迭代機制
6. 知識沉淀流程
```

## 最佳實踐

1. **先評估,再動手**: 用 MAPS-A1 評估是否值得做
2. **MVP 優先**: 從最小功能開始,快速驗證
3. **數據驅動**: 基於實際使用數據優化
4. **文檔完善**: 使用 TBRC 組織參考資料
5. **持續迭代**: 用 5A+ 循環不斷改進
6. **知識沉淀**: 記錄最佳實踐和陷阱
7. **團隊共享**: 讓資產產生複利效應

---

## 總結

使用這兩個參考文件的核心思路:

1. **MAPS 指導"做事"**: 從評估到落地的完整方法論
2. **TBRC 指導"組織"**: 結構化的內容框架
3. **明確引用**: 告訴 AI 用哪個框架的哪個部分
4. **漸進生成**: 分步驟,每步專注一個目標
5. **迭代優化**: 第一版不完美,持續改進

記住: **好的 Skill 是迭代出來的,不是一次設計出來的。**

開始創建你的第一個 Skill 吧! 🚀
